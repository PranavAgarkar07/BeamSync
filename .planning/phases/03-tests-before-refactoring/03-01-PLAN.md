  <action>Add to `beamsync/event_dispatcher_test.go`: (1) empty and negative buffer sizes fall back to `eventDispatcherBufferSize` (1024) — use the blocking-callback construction: the callback signals entry via a closed channel and then blocks on a release channel, wait for the entry signal so the worker is provably blocked, then emit 1024 jobs through `newEventDispatcher(0)` and 1024 jobs through `newEventDispatcher(-1)`, asserting all 1024 emits return true and the 1025th returns false with `DroppedCount()` incremented by exactly 1; (2) drop-on-full uses the black-box seam and the SAME primer construction as leg (1) — for a dispatcher of capacity N, first emit one primer job whose callback closes an `entered` channel and then blocks on a `release` channel, wait for `entered` so the worker is provably blocked inside the callback and the queue is empty and undrainable, then emit exactly N jobs asserting all N return true, then emit one more asserting it returns false and `DroppedCount()` equals exactly 1, then release. Apply this to `newEventDispatcher(1)` (1 job true, 2nd false) and `newEventDispatcher(2)` (2 jobs true, 3rd false) — the drop threshold is capacity+1, not capacity. Do NOT assert "the second emit returns false" without the primer step: the worker dequeues its first job immediately, so without the primer the second emit can return true and the assertion is a scheduler coin-flip; (3) panic recovery — emit a job whose callback panics, then emit a healthy job, and assert the healthy event is delivered within 1 second.</action>

    - with the worker provably blocked inside the callback (primer job signals entry before blocking), capacity N emits succeed and the capacity+1 emit returns false with `DroppedCount()` incremented by exactly 1 — proving the drop threshold is capacity+1, not capacity
    - the dispatcher survives a panicking callback and delivers the next event
  </acceptance_criteria>
